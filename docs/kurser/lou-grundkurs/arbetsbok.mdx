# Arbetsbok och checklistor

Arbetsboken är kursens praktiska stöd. Använd den parallellt med teoridelarna eller som kontrollista i en verklig upphandling. Syftet är att göra kunskapen **handlingsbar**.

<Note type="info">
  <strong>Arbeta aktivt</strong><br />
  Välj gärna en verklig eller påhittad upphandling och fyll i punkterna med konkreta svar. Det gör det mycket lättare att se var underlaget är starkt och var det finns luckor.
</Note>

## 1. Behovsanalys

Använd innan krav och lösning låses.

- [ ] Vilket verksamhetsproblem ska lösas?
- [ ] Vilket resultat behöver verksamheten uppnå?
- [ ] Vilka användare eller verksamheter berörs?
- [ ] Vad fungerar dåligt i nuläget?
- [ ] Vilka delar är verkliga behov och vilka är bara dagens lösning?
- [ ] Vilka krav är kritiska och vilka är önskemål?
- [ ] Hur ska vi veta efter avtalsstart att behovet faktiskt är löst?

### Skriv en behovsformulering

Försök formulera behovet på tre meningar utan att nämna en viss leverantör, produkt eller teknisk lösning.

<Note type="tip">
  <strong>Kontroll</strong><br />
  Om behovsbeskrivningen redan innehåller exakt hur leverantören ska organisera arbetet kan ni ha låst lösningen för tidigt.
</Note>

## 2. Marknadsanalys

| Fråga | Ditt underlag |
|---|---|
| Vilka leverantörstyper finns? | |
| Hur koncentrerad är marknaden? | |
| Vilka alternativa lösningar finns? | |
| Vilka prismodeller används normalt? | |
| Vilka krav är sannolikt kostnadsdrivande? | |
| Vilka krav kan begränsa konkurrensen? | |
| Finns etablerings- eller övergångsrisker? | |
| Finns relevanta standarder eller certifieringar? | |

### Kontrollfrågor

- [ ] Har vi bara pratat med marknadsledarna eller även mindre aktörer?
- [ ] Har vi dokumenterat vilken information som påverkat vår strategi?
- [ ] Har marknadsanalysen lett till något konkret beslut?

## 3. Värdeberäkning

Ta med hela den planerade affären.

| Post | Uppskattat värde |
|---|---:|
| Grundperiod | |
| Förlängningsoptioner | |
| Volymoptioner | |
| Tilläggstjänster | |
| Övrig ersättning som ska beaktas | |
| **Totalt uppskattat värde** | |

- [ ] Är värdet beräknat exklusive moms där reglerna kräver det?
- [ ] Har samtliga optioner och förlängningar beaktats?
- [ ] Finns liknande behov som måste bedömas tillsammans?
- [ ] Är beräkningen dokumenterad och möjlig att förklara i efterhand?

## 4. Kravgranskning

För varje viktigt krav, kontrollera:

| Kontroll | Fråga |
|---|---|
| **Behov** | Vilket konkret behov eller vilken risk hanterar kravet? |
| **Relevans** | Har kravet tydlig koppling till kontraktet? |
| **Proportionalitet** | Är nivån högre än vad som faktiskt behövs? |
| **Tydlighet** | Kan två leverantörer rimligen tolka kravet på samma sätt? |
| **Bevisning** | Hur ska leverantören visa att kravet är uppfyllt? |
| **Kontroll** | Hur ska myndigheten kontrollera uppfyllelsen? |
| **Avtal** | Behöver kravet fortsätta gälla under leveransen? |

<Note type="warning">
  <strong>Varningssignal</strong><br />
  Krav som saknar tydligt behov, bevisning eller uppföljningsmetod bör granskas en gång till innan annonsering.
</Note>

## 5. Utvärderingsmodell – stresstest

Testa modellen innan den publiceras.

Skapa minst fyra hypotetiska anbud:

1. lägst pris men bara godkänd miniminivå,
2. högst kvalitet men högre pris,
3. balanserat pris och kvalitet,
4. extremt pris eller extrem kvalitet.

Kontrollera sedan:

- [ ] ger modellen det resultat ni faktiskt avsett?
- [ ] kan en liten skillnad ge orimligt stor poängeffekt?
- [ ] kan ett extremt pris dominera hela modellen?
- [ ] är varje kvalitetsnivå tillräckligt tydligt beskriven?
- [ ] går samma bedömning att tillämpa konsekvent på alla anbud?
- [ ] är beräkningsmodellen möjlig att förklara för en leverantör?

## 6. Avtal och uppföljning

För varje viktig skyldighet:

| Fråga | Svar |
|---|---|
| Vad ska levereras? | |
| Hur mäts det? | |
| Hur ofta följs det upp? | |
| Vilken datakälla används? | |
| Vem ansvarar för uppföljningen? | |
| Vad händer vid avvikelse? | |
| När eskaleras problemet? | |

### Kontroll före avtalsstart

- [ ] Är alla mervärden som gav poäng fångade i avtalet?
- [ ] Är prismodellen tillräckligt tydlig för att undvika oväntade tillägg?
- [ ] Finns regler för ändringar och beställningar?
- [ ] Finns etableringsplan?
- [ ] Finns exit- och överlämningsvillkor?
- [ ] Är rapporteringskraven definierade?

## 7. Dokumentationskontroll

Bra dokumentation ska göra processen spårbar.

- [ ] behovsanalys
- [ ] marknadsanalys
- [ ] värdeberäkning
- [ ] val av förfarande och motivering
- [ ] krav och koppling till behov
- [ ] utvärderingsmodell och tester
- [ ] frågor, svar och rättelser
- [ ] kvalificerings- och anbudsprövning
- [ ] poängsättning och bedömningsanteckningar
- [ ] tilldelningsbeslut
- [ ] avtal
- [ ] uppföljning och avvikelser
- [ ] beslut om eventuella avtalsändringar

## 8. Leverantörens kontrollista

Kursen är relevant även från leverantörssidan. Innan ett anbud lämnas bör leverantören kontrollera:

- [ ] lämnar rätt juridisk enhet anbud?
- [ ] uppfylls samtliga kvalificeringskrav?
- [ ] finns rätt bevis för varje krav?
- [ ] är samtliga obligatoriska krav besvarade?
- [ ] är alla bilagor kompletta och aktuella?
- [ ] är priset beräknat enligt exakt efterfrågad modell?
- [ ] är mervärden beskrivna på det sätt som faktiskt ger poäng?
- [ ] har avtalsrisker analyserats?
- [ ] är frågor ställda före sista frågedag?
- [ ] finns intern deadline före extern deadline?
- [ ] är slutversion och inlämningskvitto sparade?

## 9. Slutlig kvalitetskontroll

Ställ fem frågor innan en upphandling annonseras eller ett anbud lämnas:

1. **Förstår en utomstående vad som ska uppnås?**
2. **Kan varje viktigt krav förklaras och verifieras?**
3. **Ger utvärderingen ett rimligt resultat även i extrema scenarier?**
4. **Följer avtalet det som faktiskt konkurrensutsattes och premierades?**
5. **Kan de viktigaste besluten förklaras i efterhand med dokumenterat underlag?**

<Note type="success">
  <strong>Använd arbetsboken flera gånger</strong><br />
  Den största nyttan kommer när samma struktur används återkommande. Då blir det lättare att upptäcka mönster, förbättra besluten och minska risken att kritiska moment missas.
</Note>
